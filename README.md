# Telegram Бот с OpenRouter

Приватный бот-собеседник: отвечает только пользователям из белого списка по Telegram ID.

## Быстрый старт

### 1. Получите токен бота
Откройте [@BotFather](https://t.me/BotFather) в Telegram:
```
/newbot
```
Придумайте имя и юзернейм (должен заканчиваться на `bot`).
Сохраните полученный **BOT_TOKEN**.

### 2. Получите API ключ OpenRouter
Зарегистрируйтесь на [openrouter.ai](https://openrouter.ai) и получите API ключ
(workspace → Settings → API Keys).

### 3. Настройте Railway

1. Создайте репозиторий GitHub и загрузите файлы проекта.
2. В Railway: **Create → GitHub Repository** → выбрать репозиторий.
3. Добавьте переменные окружения:

| Переменная | Обязательна | Значение |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `OPENROUTER_API_KEY` | да | ключ `sk-or-v1-...` |
| `MODEL` | нет | модель OpenRouter, по умолчанию `meta-llama/llama-3.1-8b-instruct` |
| `ALLOWED_USER_IDS` | да | числовые Telegram ID через запятую |
| `ALLOWED_USERNAMES` | нет | username через запятую без `@`, запасной вариант |
| `MAX_HISTORY` | нет | сколько сообщений диалога помнить, по умолчанию `20` |

4. Deploy — Railway соберёт образ по `Dockerfile`.

`PORT` не нужен: бот работает через long polling.

## Доступ

Все сообщения проходят через `AccessMiddleware`:
- `user.id` в `ALLOWED_USER_IDS` → доступ разрешён;
- иначе username сравнивается с `ALLOWED_USERNAMES`;
- иначе бот отвечает «Этот бот приватный.» **и показывает отправителю его ID**,
  а в логах появляется строка `Отказ в доступе: id=... username=@...`.

Если оба списка пусты, бот не отвечает никому и пишет об этом в лог при старте.

## Как узнать Telegram ID

- Тот, кому нужен доступ, пишет боту — в ответе на отказ будет его ID.
- Или он открывает [@userinfobot](https://t.me/userinfobot) и жмёт `/start`.
- Свой ID можно узнать командой `/id` (доступна разрешённым пользователям).

Затем впишите ID в `ALLOWED_USER_IDS` (через запятую) и перезапустите сервис.

## Память диалога

История хранится в памяти процесса, отдельно для каждого чата:

- каждый запрос уходит в OpenRouter вместе с последними сообщениями диалога;
- хранится не больше `MAX_HISTORY` сообщений (по умолчанию 20, то есть ~10 пар «вопрос-ответ»),
  старые вытесняются;
- `/reset` очищает историю текущего чата;
- после перезапуска контейнера история теряется — постоянного хранилища нет.

## Возможности
- ✅ Отвечает на любые текстовые сообщения через выбранную модель OpenRouter
- ✅ Белый список по Telegram ID (username — запасной вариант)
- ✅ Модель меняется переменной `MODEL`, без правки кода
- ✅ Индикатор «печатает…» пока модель думает

## Обновление
Пуш в GitHub → Railway автоматически пересобирает и перезапускает бота.
